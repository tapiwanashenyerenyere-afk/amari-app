How We Work Together

The operating system

This is the standing agreement for AMARI work: concrete state, visible decisions, no hidden context, and no launch-critical facts trapped in chat.

One board owns launch state Anything launch-critical gets reflected here or in a linked repo doc. Chat is useful, but this board is what a future session can reopen.
Every major item gets subtasks Each task carries smaller checkable pieces, key configuration, and a decision network so progress is not vague.
Decisions show their connections When a choice affects another system, the connection is written under the task. When it does not, that independence is explicit too.
Security and taste move together AMARI should feel sharp and culturally specific, while release engineering, privacy, RLS, app review, and store compliance stay disciplined.
